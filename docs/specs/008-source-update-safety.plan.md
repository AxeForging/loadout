**Recorded deviation (spec req 10):** a "pure addition" update still snapshots `loadout.yaml` + `sources.lock.yaml` — every apply rewrites them, and restoring them is exactly what undoes a bad pin move. Only artifact trees follow the "nothing overwritten, nothing snapshotted" rule.

## Risks

- **Backfill correctness** is the migration: old stores have no `sourceHash`. Mitigation: reconstruct baseline from the pinned commit (full clone); unreachable pin degrades to labeled legacy two-way, never a silent guess. No format version bump; older binaries ignore the field. Rollback: revert PR — stamped hashes are inert.
- **`--yes` semantics change** (no longer discards edits) is an intentional break — `feat!` title + README callout. Scripts that relied on clobbering must add `--force-discard`.
- **Lock scope creep**: only mutation entry points take the lock; if a call path is missed the failure mode is today's behavior (no lock), never a deadlock. Stale-steal keeps a crashed process from bricking the store.
- **Snapshot adapter** must not disturb 004's format — reuse `captureSnapshot` unchanged; only entry construction is new. Restore of store paths is covered by an integration round-trip before merge.
- **PR size**: mitigated by dependency-ordered commits (domain → source → store → cli → web → docs), each green on its own.
